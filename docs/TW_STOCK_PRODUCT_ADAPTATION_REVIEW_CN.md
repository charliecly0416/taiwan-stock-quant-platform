# 台股产品适配与模拟账户方案评审

日期：2026-06-05

## 1. 总体结论

`docs/TW_STOCK_PRODUCT_ADAPTATION_AND_SIM_ACCOUNT_PLAN_CN.md` 的方向合理，可以实施，但必须收敛范围。

它最正确的判断是：当前台股平台不应该把左侧所有通用交易功能完整适配台股，而应该围绕“研究信号是否值得人工复盘、历史和模拟验证是否有效”建立闭环。

符合当前第一要务：

- 实用：用户真正需要知道今天看什么、为什么看、历史表现如何。
- 简单：不要让用户先理解 qlib run、provider、broker、机器人、策略引擎。
- 准确：成交规则、数据日期、复权口径、收益统计必须说清楚。
- 清晰：研究、模拟、真实交易必须隔离。

## 2. 合理需求

建议纳入后续执行：

- 台股主入口收敛为“台股研究”。
- 运维信息折叠到高级区，不出现在主视图。
- 个股研究详情聚合 qlib、QuantDinger 趋势、K 线、cross-analysis、Agent 解释。
- 新增“台股模拟账户”，用于人工确认后的模拟买卖和收益验证。
- 从 Top30/Top50/cross-analysis/Agent 生成模拟交易草稿，但必须二次确认。
- 只读历史验证和模拟账户分开：回测验证规则，模拟账户验证用户实际复盘决策。
- 所有模拟账户接口固定返回 `simulation_only=true`、`connects_to_broker=false`、`real_orders_enabled=false`。

## 3. 需要收敛的点

原方案中有些内容应推迟：

- 第一版不要做多个复杂账户策略。先支持一个默认账户，再扩展多账户。
- 第一版不要做复杂绩效归因。先做现金、持仓、市值、收益率、基础净值曲线。
- 第一版不要做真实 next open 强制成交。如果下一交易日开盘价缺失，应保持草稿或 pending，不要伪造成交。
- 第一版不要把 Agent 直接创建订单。Agent 只能生成草稿说明，用户点击确认后才创建模拟订单。
- 第一版不要接入真实 broker、quick-trade、机器人或 live 策略。

## 4. 推荐实施步骤

按 5 步执行：

1. Phase 1：信息架构收敛与台股研究主视图整理。
2. Phase 2：模拟账户后端核心 MVP。
3. Phase 3：模拟账户前端 MVP。
4. Phase 4：研究信号到模拟交易草稿联动。
5. Phase 5：绩效验证、K 线标记与全流程验收。

每一步完成后提交报告，由审核者判断是否进入下一步。
