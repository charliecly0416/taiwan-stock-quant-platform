## 1. 审查结论

Phase4A 在安全边界上通过，但**还不完全符合用户第一性原则**，因此**不放行进入真实只读接入实现审查**。

本轮好的部分：

- 首屏被强行收敛到 4 个信息单元，方向对；
- 高百分比历史回放数值被挡在首屏外，方向对；
- `readonly_disclaimer` 固定可见，方向对；
- `why_no_action` 被提升为首屏核心，方向对。

但仍有两个核心问题：

1. **首屏第一信息单元仍然是“方法角色”，不是“用户现在该看什么”**；
2. **详情层把历史回放数值过度等级化成低/中/高，牺牲了准确性和实用性**。

这两个问题分别伤害了：

- “简单/清晰”：用户第一眼没有直接得到“我现在该看什么”；
- “准确/实用”：详情层过度抽象，无法支持认真复盘。

因此本轮需要进入 Phase4B，只修正展示契约，不写实现代码。

## 2. 是否符合用户第一性原则

### 2.1 简单：部分符合

Phase4A 已经比之前更收束，但首屏 4 单元里第一个是：

```text
方法角色
```

这更像系统内部分类，而不是用户问题本身。

主线文档要求用户最终首先得到：

1. 今天哪些台股更值得先看；
2. baseline 和 rerank 是否一致；
3. 当前市场环境下是否适合动作；
4. 不动作时究竟为什么不动。

而 Phase4A 的首屏结构是：

1. 方法角色
2. 为什么不动
3. 当前取舍
4. 只读边界

这意味着首屏仍然缺少：

```text
“现在值得先看什么 / 当前属于哪类观察结论”
```

用户第一眼先看到“基准对照 / 高换手研究参考 / 换手控制研究参考”，并不比看到“当前不动作原因 + 当前观察重点”更有帮助。

### 2.2 准确：不完全符合

Phase4A 为了避免误导，把高数值完全推到后面，这是对的；但它进一步规定：

```text
详情层默认也不展示精确高百分比，只展示低 / 中 / 高
```

这会带来新的准确性问题。

因为：

- `drawdown_summary`
- `action_count_summary`
- `turnover_summary`
- `relative_to_top50_adaptive`

如果全部只剩等级描述，用户无法区分“略高”和“极高”的差异，人工复盘也会失真。

用户第一性原则里的“准确”不是“尽量少数字”，而是：

```text
在不误导的前提下，保留真实能力边界和有效差异。
```

所以正确做法应该是：

- 首屏避免精确高数值；
- 详情层允许展示**受约束的精确值**；
- 但必须明确它们是历史回放指标，而且必须和 tradeoff 同屏。

### 2.3 清晰：部分符合

`why_no_action` 模板现在比较清楚，这一点是通过的。

但 `research_role` 的最终中文仍偏系统视角：

- 基准对照
- 高换手研究参考
- 换手控制研究参考
- 风险复盘参考

这些比英文好，但仍然不是最贴近用户的标签。至少还需要明确：

- 这些标签是否展示给普通用户；
- 还是仅作为次级说明存在；
- 首屏主标题是否应该换成用户更能立即理解的短语。

### 2.4 实用：部分符合

Phase4A 对详情层/调试层做了分层，这是好的。

但把详情层也过度等级化，会削弱人工复盘的实用性。真正实用的结构应该是：

- 首屏：极简、结论化、避免误导；
- 详情层：保留受约束的真实回放指标；
- 调试层：保留 trace 与原始对象。

现在首屏和详情层之间的差异还不够合理。

---

## 3. 主要问题

### P1：首屏第一单元过于系统视角，不够用户视角

当前首屏第一个单元是“方法角色”。

这不够符合：

```text
今天谁值得先看
为什么
为什么不动
```

的方法顺序。

Phase4B 必须把首屏信息顺序改成更贴近用户问题的结构。至少应优先考虑：

1. 当前观察结论 / 当前不动作原因
2. 当前取舍摘要
3. 方法角色（次级）
4. 只读边界

而不是把“方法角色”放在第一位。

### P1：详情层默认完全等级化，损伤准确性和实用性

Phase4A 把详情层的：

- drawdown
- action_count
- turnover
- relative_to_top50_adaptive

都倾向于改写成等级描述。

这一步过头了。

应改为：

```text
首屏：等级化
详情层：受约束的精确历史回放指标 + 等级化解释 + tradeoff 同屏
调试层：原始 trace
```

否则用户既看不到首屏之外的真实差异，也无法做严肃复盘。

## 7. Phase4B 必须修正的内容

### 7.1 重新排序首屏单元

必须冻结一个更用户导向的首屏顺序。

推荐顺序：

1. 当前为什么不动 / 当前观察结论
2. 当前取舍摘要
3. 方法角色
4. 只读边界

如执行者不同意该顺序，必须给出更符合“今天谁值得先看 / 为什么不动”的替代顺序。

### 7.2 重新定义详情层精度

必须明确：

- 首屏不用精确高数值；
- 详情层允许展示受约束的精确历史回放指标；
- 这些精确值必须始终与 tradeoff 同屏；
- 不允许单独突出净值变化数字。

### 7.3 冻结“用户标签”与“系统标签”边界

必须明确：

- 哪些标签给用户看；
- 哪些标签只留给系统/调试层；
- `research_role` 的用户化短标签和系统内部值如何一一对应。
