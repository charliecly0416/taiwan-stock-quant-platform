# Phase4A 产品展示契约冻结执行报告

生成时间：2026-06-14

主线依据：`docs/TW_STOCK_LTR_RERANK_REGIME_AND_TURNOVER_PLAN_CN.md`

执行依据：`docs/tw_ltr_rerank_regime_turnover/PHASE4_REVIEW_AND_PHASE4A_PRODUCT_DISPLAY_CONTRACT_WORK_CN.md`

## 1. 本轮目标

本轮只冻结产品展示契约，把 Phase3C payload 收束成用户第一性原则下的最小展示结构。

本轮不做前端实现，不做 API 实现，不写测试，不改 payload，不改 replay / model / training 代码，不进入产品接入。

冻结原则：

- 简单：首屏只保留用户第一眼需要的信息；
- 准确：所有历史回放信息都保持研究语义；
- 清晰：普通用户不需要理解工程字段；
- 实用：能回答“为什么不动”和“这个方法是什么角色”。

## 2. 首屏最小展示结构

首屏固定只允许 4 个信息单元：

| 单元 | 字段来源 | 展示方式 | 目的 |
| --- | --- | --- | --- |
| 方法角色 | `research_role` 映射中文 | 短标签 | 先告诉用户这是什么类型的研究参考 |
| 为什么不动 | `why_no_action` 改写模板 | 一句话 | 直接回答用户最关心的问题 |
| 当前取舍 | 由 action / turnover / drawdown 汇总生成 | 一句话 | 说明动作频率、换手压力和回撤取舍 |
| 只读边界 | 固定文案 | 常驻小字 | 防止误读为操作指令 |

首屏不展示：

- 精确费用后净值变化；
- 精确历史回放最大回撤；
- 精确动作次数；
- 精确 turnover proxy；
- `summary_notes[]`；
- `source_trace`；
- schema / created_at / safety object。

## 3. 详情层 / 调试层字段分层

### 3.1 详情层

详情层用于人工复盘，可展示：

| 字段 | 处理方式 |
| --- | --- |
| `drawdown_summary` | 改写为“历史回放最大回撤：低 / 中 / 高” |
| `action_count_summary` | 改写为“历史回放动作频率：低 / 中 / 高” |
| `turnover_summary` | 改写为“历史回放换手压力：低 / 中 / 高” |
| `relative_to_top50_adaptive` | 改写为相对 Top50 adaptive 的取舍说明，不展示单独高数值 |
| `data_quality_note` | 保留共同日期、缺分、price audit 摘要 |

详情层仍不突出精确高百分比；如确需展示，必须放在“历史回放明细”折叠项内，并和动作、换手、回撤同时出现。

### 3.2 调试 / 审查层

只给审查或调试使用，不进入普通产品展示：

- `source_trace`
- `schema_version`
- `created_at`
- `safety_boundary`
- 原始 `summary_notes[]`
- 原始 payload JSON

### 3.3 永不进入产品展示

- 脱离“历史回放”的效果判断；
- 把任一 method 包装成主推荐的文案；
- 把 qlib / LTR 分数解释为回报、概率或配置比例的文案。

## 4. `research_role` 最终中文

| research_role | 最终中文标签 | 展示说明 |
| --- | --- | --- |
| `baseline` | 基准对照 | 用来比较其他研究方法，不代表优先选择 |
| `aggressive_rerank_research` | 高换手研究参考 | 更跟随 rerank，必须同时提示动作和换手压力 |
| `turnover_control_research` | 换手控制研究参考 | 更强调少动作和换手控制 |
| `risk_review_reference` | 风险复盘参考 | 用于观察低动作和回撤取舍 |

不在普通页面直接显示：

- baseline
- aggressive
- rerank
- turnover proxy
- risk review

这些英文或研究术语只保留在调试层。

## 5. `why_no_action` 模板

首屏 `why_no_action` 固定为一句话，模板如下：

```text
今天不动作的主要原因：{原因短语}。
```

允许的原因短语只来自以下集合：

| 原因类型 | 原因短语 |
| --- | --- |
| 候选差距 | 候选排序差距不够明显 |
| 动作预算 | 最近窗口动作预算不足 |
| 持有期 | 仍在最短观察期内 |
| 市况过滤 | 当前市况要求更谨慎 |
| 数据质量 | 当日数据不足以形成解释 |
| 价格缺失 | 缺少可用价格，保持只读观察 |
| 共同日期 | 当日不在共同回放日期集合内 |

不得把 `why_no_action` 写成：

- 对未来走势的判断；
- 对用户行为的指令；
- 对某个方法优劣的结论；
- 对配置比例的提示。

## 6. `tradeoff_summary` 中文模板

首屏当前取舍固定为一句话，模板如下：

```text
历史回放取舍：{动作频率}，{换手压力}，{回撤水平}。
```

取值集合固定：

| 项 | 允许值 |
| --- | --- |
| 动作频率 | 动作偏少 / 动作适中 / 动作偏多 |
| 换手压力 | 换手压力较低 / 换手压力中等 / 换手压力较高 |
| 回撤水平 | 回撤较低 / 回撤中等 / 回撤较高 |

首屏不展示精确数字。详情层如展示数值，只能在同一段同时展示动作、换手和回撤，不能单独突出费用后净值变化。

## 7. `readonly_disclaimer` 最终固定文案

最终固定文案：

```text
仅供只读研究复盘，不构成操作建议，不会产生任何真实执行动作。
```

展示要求：

- 首屏常驻可见；
- 每个方法卡片或方法详情均可见；
- API top-level 与 method-level 均保留；
- 不允许由前端自行改写成更强语气或更弱语气。

## 8. 高数值展示规则

冻结单一规则：

```text
高百分比历史回放数值不进首屏；产品层默认展示等级化取舍，不展示精确高百分比。
```

具体规则：

1. 首屏不展示 `net_return_summary` 的精确百分比；
2. 详情层默认也不展示精确高百分比，只展示“历史回放费用后净值变化：低 / 中 / 高”；
3. 如果审查者后续要求保留精确数值，只能放在“历史回放明细”折叠项内；
4. 精确数值出现时，必须与动作频率、换手压力和回撤水平同屏；
5. 不允许按精确费用后净值排序展示方法；
6. 不允许把高数值用于强调某方法更适合用户。

等级化规则建议：

| 指标 | 展示等级 |
| --- | --- |
| 费用后净值变化 | 低 / 中 / 高 |
| 历史回放最大回撤 | 低 / 中 / 高 |
| 历史回放动作次数 | 偏少 / 适中 / 偏多 |
| 历史回放换手压力 | 较低 / 中等 / 较高 |
