# 台股平台功能适配与模拟证券账户实现方案

日期：2026-06-05

## 1. 结论

当前项目不应该把左侧所有功能都“完整适配台股”。用户最需要的是：信息清晰、口径一致、操作简单、结果可验证。

建议把台股产品先收敛成一条主线：

1. 今日研究排名：Top30/Top50、排名变化、交叉分析。
2. 个股研究页：K 线、QuantDinger 趋势、qlib 排名、数据口径。
3. 只读历史验证：回测和模拟账户。
4. Agent 研究助手：解释为什么在榜、风险点、复盘提示。

左侧已有的指标、策略、机器人、账户、券商等功能不应直接全部开放给台股用户。它们很多来自通用交易平台语境，容易让用户误解为可以自动买卖或真实下单。台股当前应优先做“研究与验证”，不是 live trading。

## 2. 用户视角的问题

现在用户进入系统会看到很多功能：指标、策略、机器人、账户、交易、AI 分析、台股监控等。问题是：

- 功能太多，但用户不知道哪些适用于台股。
- 通用交易词汇太多，例如买入、卖出、机器人、账户、策略运行，容易和真实交易混淆。
- qlib、QuantDinger、K 线、AI 分析之间如果口径不统一，用户会觉得系统不可信。
- 只有排名和趋势还不够，用户会自然想知道：这些研究信号历史上到底有没有用。

因此最有价值的下一步不是继续增加复杂功能，而是建立一个简单的验证闭环：

> 研究信号 → 用户确认模拟操作 → 用真实行情计价 → 统计收益/亏损 → 复盘信号是否有效。

## 3. 功能适配优先级

### P0：必须适配，直接提高可用性

#### 3.1 台股研究首页

目标：用户一进来就知道今天该看什么。

应保留：

- 今日 Top30/Top50。
- 新进榜、掉出榜、持续在榜。
- qlib 日期、QuantDinger 日期、数据是否一致。
- 个股 K 线查看。
- 交叉分析：qlib 排名与 QuantDinger 趋势是否一致。

应隐藏或折叠：

- dry-run。
- qlib ops 细节。
- run_id、recorder_id 等维护字段。
- provider publish、accepted latest 等内部运维信息。

这些信息可以放在“高级信息与维护工具”里，不应该出现在主视图。

#### 3.2 个股研究详情

目标：用户点一个股票后，能快速看懂它为什么值得复盘。

建议聚合成一个页面或抽屉：

- 股票代码和中文名。
- qlib 排名、分数、日期。
- QuantDinger 趋势、趋势分、最新行情日期。
- K 线图和短线涨跌。
- 是否新进榜、连续在榜天数、排名变化。
- 数据质量提示。
- Agent 简短解释。

禁止把 qlib_score 解释成收益率、胜率、上涨概率或买入概率。

#### 3.3 模拟证券账户

这是最值得新增的功能。

目标：验证研究信号是否真的有用，而不是只看模型分数。

核心原则：

- 只做模拟，不连接 broker。
- 不提交真实订单。
- 不调用 quick-trade。
- 不自动把 Agent 回答变成交易。
- 每一笔模拟买入/卖出都必须由用户确认。
- 结果按真实 K 线或最新行情计价。

用户价值：

- 可以建立一个或多个模拟账户。
- 可以根据研究排名或 Agent 解释手动加入模拟交易。
- 可以看到持仓盈亏、账户收益率、最大回撤。
- 可以比较“跟随 Top30/Top50 信号”是否优于大盘或自选基准。

### P1：可以适配，但要收敛入口

#### 3.4 只读回测

已有基础能力，应该从“复杂策略工具”降级成用户容易理解的历史验证入口。

建议入口文案：

- “历史模拟”
- “验证这个信号过去表现”
- “用过去数据复盘”

不建议主视图出现：

- 策略源码编辑器。
- 机器人运行。
- live mode。
- broker 参数。

初期只提供固定模板：

- MA 交叉。
- 趋势跟随。
- qlib TopN 换仓模拟。
- qlib + QuantDinger 一致性过滤模拟。

#### 3.5 Agent 研究助手

Agent 应该服务于解释，而不是替用户下决策。

可做：

- 解释某股票为什么在榜。
- 总结今天新进榜和掉出榜。
- 解释 qlib 与 QuantDinger 是否一致。
- 生成“人工复盘清单”。
- 把某条研究信号发送到模拟账户草稿。

不做：

- “建议真实买入”。
- “目标仓位”。
- “上涨概率”。
- “保证收益”。
- 自动下单或连接券商。

### P2：暂缓适配或只读化

#### 3.6 指标 IDE

指标功能适合高级用户，但不适合放在台股主流程里。

建议：

- 保留给高级模式。
- 支持 TWStock K 线输入。
- 输出只读指标和回测结果。
- 不允许一键转 live 策略。

#### 3.7 策略功能

当前策略系统更像通用交易平台能力。台股阶段不建议直接适配 live 策略。

可以做：

- 保存“研究策略模板”。
- 只读回测。
- 模拟账户手动确认交易。

暂缓：

- 自动运行策略。
- 自动调仓。
- 真实下单。

#### 3.8 机器人

暂不建议适配台股。

原因：

- 机器人天然暗示自动交易。
- 台股研究信号目前还在验证阶段。
- 容易破坏用户对研究/交易边界的理解。

如果必须保留，只能做“研究提醒机器人”，不是交易机器人。

#### 3.9 账户 / broker / quick-trade

不建议接入台股真实账户。

建议左侧对台股用户显示：

- 模拟账户。
- 研究账户绩效。
- 不显示 broker 连接。
- 不显示 quick-trade。

真实券商功能应保持独立，不与台股研究页面混在一起。

## 4. 模拟证券账户设计

### 4.1 用户故事

用户希望：

1. 创建一个模拟账户，例如“我的台股研究账户”。
2. 设置初始资金，例如 1,000,000 TWD。
3. 在 Top30/Top50 或个股详情中点击“加入模拟交易草稿”。
4. 系统给出基于规则的模拟动作草稿。
5. 用户确认后，生成模拟成交。
6. 每天用真实行情更新市值和盈亏。
7. 用户查看账户表现，判断研究信号是否有效。

### 4.2 页面设计

建议新增左侧一级入口：

> 台股模拟账户

页面只保留 4 个区块：

1. 账户概览

- 总资产。
- 现金。
- 持仓市值。
- 累计收益率。
- 今日盈亏。
- 最大回撤。

2. 持仓

- 代码 / 名称。
- 持股数量。
- 成本价。
- 最新价。
- 浮动盈亏。
- 关联研究信号：qlib rank、trend label、cross category。

3. 模拟交易

- 买入 / 卖出。
- 股票代码。
- 股数，默认按 1000 股整张。
- 价格来源：最新收盘价或下一交易日开盘价。
- 手续费和交易税估算。
- 用户确认按钮。

4. 复盘表现

- 账户净值曲线。
- 与加权指数或 0050 对比。
- 按来源拆分：手动交易、Top30 信号、Agent 草稿。
- 胜率、平均盈亏、持有天数。

### 4.3 操作流程

最简单流程：

1. 用户在今日排名点击某股票。
2. 详情页显示“加入模拟账户”。
3. 弹出确认框：
   - 账户。
   - 动作：模拟买入 / 模拟卖出。
   - 数量。
   - 参考价。
   - 手续费估算。
   - 研究依据。
4. 用户确认。
5. 进入模拟账户查看持仓。

不要让用户先配置复杂策略，也不要要求用户理解 qlib 内部 run。

### 4.4 模拟动作来源

模拟交易可以有 3 种来源：

1. 用户手动输入。
2. 从 qlib Top30/Top50 生成草稿。
3. 从 Agent 研究解释生成草稿。

但所有草稿必须经过用户确认。

建议文案：

- “生成模拟交易草稿”
- “确认模拟买入”
- “确认模拟卖出”

避免文案：

- “一键买入”
- “自动下单”
- “跟随 AI 买入”
- “目标仓位”

### 4.5 交易价格规则

为了准确且简单，第一版只支持两种成交规则：

- 当日收盘价成交：适合复盘。
- 下一交易日开盘价成交：适合验证信号延迟。

默认建议：下一交易日开盘价成交。

原因：qlib accepted latest 通常是收盘后生成的研究排序，用同一天收盘价成交会产生未来函数误解。

### 4.6 台股市场规则

第一版简化但要准确标注：

- 货币：TWD。
- 默认交易单位：1000 股。
- 可允许零股模式，但默认关闭。
- 买入扣现金。
- 卖出增加现金。
- 不允许卖空。
- 不允许现金为负。
- 手续费、交易税使用可配置默认值。
- 除权息第一版只在价格数据已复权时说明口径，不单独模拟现金股利。

### 4.8 API 建议

只读：

```text
GET /api/tw-stock/sim/accounts
GET /api/tw-stock/sim/accounts/:id
GET /api/tw-stock/sim/accounts/:id/positions
GET /api/tw-stock/sim/accounts/:id/trades
GET /api/tw-stock/sim/accounts/:id/nav
GET /api/tw-stock/sim/accounts/:id/performance
```

写入，但仅模拟：

```text
POST /api/tw-stock/sim/accounts
POST /api/tw-stock/sim/orders/draft
POST /api/tw-stock/sim/orders/:id/confirm
POST /api/tw-stock/sim/orders/:id/cancel
POST /api/tw-stock/sim/accounts/:id/revalue
```

所有响应必须包含：

```json
{
  "trading": {
    "real_orders_enabled": false,
    "connects_to_broker": false,
    "simulation_only": true
  }
}
```

## 5. 与现有功能的适配关系

### 5.1 台股研究排名

适配方式：

- 每一行增加“加入模拟交易草稿”。
- 默认动作不是直接买入，而是打开确认弹窗。
- 弹窗展示 qlib rank、score、趋势、数据日期。

### 5.2 交叉分析

适配方式：

- focus_watch / aligned 可以作为模拟买入草稿来源。
- divergent / data_review_required 默认不生成买入草稿，只生成“观察备注”。
- 所有逻辑可配置，但第一版保持保守。

### 5.3 Agent

适配方式：

- Agent 可以生成“模拟交易草稿说明”。
- Agent 不直接创建订单。
- 用户必须点击确认。

### 5.4 K 线图

适配方式：

- K 线图可显示模拟买卖点。
- 鼠标 hover 显示成交价格、盈亏、来源信号。
- 这会让用户直观看到模型是否买在高点或低点。

### 5.5 回测

适配方式：

- 回测用于批量历史验证。
- 模拟账户用于用户真实决策过程验证。
- 两者不要混成一个功能。

## 6. 不建议适配的功能

### 6.1 真实账户连接

暂不适配。

原因：当前重点是验证研究信号，而不是真实交易执行。

### 6.2 自动交易机器人

暂不适配。

如果未来要做，也应先完成模拟账户长期验证，并明确所有风险边界。

### 6.3 通用策略市场

暂不适配成台股主入口。

用户不应该被迫理解复杂策略引擎才能验证台股研究。

## 7. 推荐迭代路线

### Phase 1：信息架构收敛

目标：让用户不会被左侧功能干扰。

工作：

- 台股页面主入口改成“台股研究”。
- 隐藏或折叠运维工具。
- 左侧标记哪些功能支持 TWStock。
- 对不支持的功能显示“暂不支持台股真实交易”。

验收：

- 用户能在 30 秒内找到今日排名、个股 K 线和交叉分析。
- 页面不出现误导性的真实买卖入口。

### Phase 2：模拟账户 MVP

目标：用户可以手动记录模拟买卖并看收益。

工作：

- 创建模拟账户。
- 手动买入/卖出。
- 持仓和现金计算。
- 每日按最新 K 线计价。
- 展示净值曲线。

验收：

- 能创建账户。
- 能买入 2357、6290 等台股。
- 能卖出已有持仓。
- 不允许卖空。
- 不允许现金为负。
- 所有接口明确 `simulation_only=true`。

### Phase 3：研究信号联动

目标：把 qlib/QuantDinger 研究结果变成可验证的模拟草稿。

工作：

- Top30 行增加“模拟交易草稿”。
- cross-analysis focus_watch 支持生成草稿。
- Agent 支持解释草稿来源。
- K 线图显示模拟买卖点。

验收：

- 用户可以从榜单创建草稿。
- 草稿必须二次确认。
- 确认后写入模拟订单和成交。
- 不触发 broker、quick-trade、真实订单。

### Phase 4：绩效验证

目标：判断量化研究是否真的有价值。

工作：

- 账户收益率。
- 最大回撤。
- 胜率。
- 平均持有天数。
- 与 0050 或加权指数对比。
- 按信号来源拆分绩效。

验收：

- 用户能看到“跟随 Top30 草稿”的表现。
- 用户能看到 Agent 草稿表现。
- 用户能看到手动交易表现。
- 所有收益展示都基于真实历史/行情数据，不承诺未来收益。

## 8. 最终产品形态建议

左侧导航不应让台股用户看到一堆不适配功能。建议台股相关只保留：

1. 台股研究排行。
2. 台股模拟账户。
3. 台股历史验证。
4. 台股研究助手。

高级用户入口：

1. 指标 IDE。
2. 策略实验室。
3. 运维工具。

真实交易、broker、机器人应与台股研究主线隔离。

## 9. 风险与边界

必须明确：

- 模拟账户不是证券账户。
- 模拟成交不是实际成交。
- qlib_score 不是上涨概率。
- Agent 输出不是交易建议。
- 所有收益统计仅表示历史模拟结果。
- 不允许自动下单。
- 不连接 broker。

建议所有模拟账户页面固定显示：

```text
本页面仅用于台股研究信号的历史与模拟验证，不连接券商，不提交真实订单，不构成投资建议。
```

## 10. 推荐下一步

建议先做 Phase 1 + Phase 2。

理由：

- Phase 1 解决用户看不懂、入口混乱的问题。
- Phase 2 让用户马上能验证信号是否有效。
- 不需要先改复杂策略和机器人系统。
- 风险边界清楚，操作简单。

第一版模拟账户只需要支持：

- 一个默认模拟账户。
- 初始资金。
- 手动买入/卖出。
- 持仓盈亏。
- 净值曲线。
- 从 Top30/Top50 生成模拟交易草稿。

这比全面适配指标、策略、机器人、真实账户更符合当前项目阶段，也更符合用户真正想要的验证闭环。
