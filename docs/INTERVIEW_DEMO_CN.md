# 面试演示路线

建议 8–10 分钟，打开 `http://localhost:8000`。演示前确认 `/api/ready` 返回 200；实际日期以页面显示为准。本次验收批次为 2026-09-24，不把自然日当交易日。

## 先讲产品（约 3 分钟）

1. **总览**：这是台股研究台，冻结 Model A 生成可追溯排名，另有独立模拟账户。解释“约 1,964 支行情 → 当日流动性 150 → 策略 Top50”。
2. **排名与策略**：切换 Top30 / Top50，查看进入、离开与排名变化，说明下一交易日开盘执行的语义；分数是相对排名依据。
3. **个股行情**：输入 2330，展示价格、量能、MA20、RSI14 与研究背景。行情按标的读取，不在每次请求复制全市场数据。
4. **历史回放**：使用预填的 2025-06-23 至 2025-06-30，展示 NAV、费用、回撤、持仓和成交；费用计入现金与净值。也可展示 2026-09-21 至 2026-09-24。
5. **模型比较**：使用 2026-05-07，解释 B19R2R 从 Model A 的 150 支评分集合中过滤缺失 78F 的标的，并按原始排名递补至 50 支重排。可选历史比较窗口预填为已验证的 2026-05-07 至 2026-05-08。比较只读，不能把研究模型应用到默认策略。
6. **研究问答**：问“排名第一是谁？”或“今天候选有哪些？”，展示每日上下文和引用。当前是本地产物解释，不能声称调用远端大模型或实时预测。

## 再讲后端（约 3 分钟）

打开“系统”页，顺着模块卡片讲解，再打开 [架构图](ARCHITECTURE_CN.md)：

- **配置驱动**：`configs/product.yaml` 定义数据集、模型 stages、策略和运行参数；三个 registry 固定基线和消费者边界。
- **模块化单体**：`clean_product/` 的 data / models / strategy / replay / agent / paper 分工，Flask routes 只负责接口适配，ProductService 组合业务。
- **单向产物流**：数据 → 特征与信号 → 策略意图 → 回放与研究 API；前端不读私人实验文件，也不直接请求供应商。
- **可靠发布**：`orchestrator.py` 每次生成独立 release，成功后原子切换 active.json。失败继续服务上一份；同日重跑不覆盖旧问答来源。
- **实际运维**：展示系统页的持续运维检查、备份时间、剩余空间，以及systemd的Web/三个timer；manual与scheduled分开。解释失败保持旧批次、内容去重备份和独立目录升级；可打开部署报告展示恢复验证结果。

推荐代码查看顺序：`config.py` → `data.py` / `provider_refresh.py` → `models.py` → `strategy.py` → `orchestrator.py` → `service.py` → `backend/app/routes/tw_stock.py`。无需逐行讲整份模型或遗留实验。

## 可选展示模拟账户（约 2 分钟）

按 [运维手册](OPERATIONS_CN.md) 生成 `interview` owner 的临时令牌。创建专用账户，使用页面预填前一交易日，查看预览的 next_open、手续费和预计持仓，确认后看历史记录。重复确认有幂等保护，重置需要显式确认，账户不连接真实订单。

收尾用 [验收记录](MAINLINE_ACCEPTANCE_CN.md) 说明已测范围。讲清技术实现和可解释性；短期历史收益不能代表未来收益，影子模型新日期特征仍是独立研究工作。
